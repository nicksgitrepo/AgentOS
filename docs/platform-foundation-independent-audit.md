## Runtime visible-task parity addendum

The inventory validator previously treated its portable assignment references
and count fields as sufficient evidence of visible task parity. That was too
weak for admission: synthetic references can describe work that is not present
in the host.

The workflow seam now requires a runtime-only visible-task registry containing
exactly one visible task and isolated runtime worktree for every inventory
target. It validates the inventory assignment, unique opaque runtime task and
worktree identifiers, visible lifecycle, and exact target coverage. The
registry is not persisted with chat content, private paths, credentials, or
secrets. Missing or mismatched records fail closed before roster compilation.

The current host readback contains `37` relevant AgentOS worktree tasks, all
feature-shaped, and `7` visible platform-shaped tasks for lanes 01 through 07.
Lanes 08 through 12 remain undiscoverable. This still does not prove the
required `49` target registry or release the platform gate. The partial
readback is recorded rather than inferred into full parity.

## Workflow binding addendum

The visible-task repair is now enforced through the phase entry seam, not only
through the inventory compiler. Workflow state carries both the canonical
inventory digest and the normalized visible-task-parity digest. Bootstrap and
the phase starter revalidate those digests against the supplied inventory and
runtime registry before either platform or feature work begins. The public
kernel no longer exposes an unbound roster compiler as an admission path.

Static evidence after this repair: changed modules pass syntax checks, changed
JSON parses, diff hygiene passes, and all `237` normative bindings match. This
does not change PF-004: the required all-49 runtime registry and five missing
platform task slots remain unresolved.

The follow-up hardening also binds every workflow transition and task closeout
through the same inventory and visible-task readback, and removes the direct
unbound transition helper from the public kernel surface. This prevents a
caller from bypassing parity after initial workflow construction.

The registry contract now also requires an active, target-bound goal digest and
the exact inventory report path for each visible task. A visible thread without
the assigned lane goal is therefore not admitted as a governed lane.

`INVENTORY_BINDING_REQUIRED` and `VISIBLE_TASK_PARITY_REQUIRED` admission
outcomes instead of generic schema failures. This improves recovery routing but
does not waive PF-004 or release feature admission.

## Evidence privacy repair addendum

The evidence receipt boundary previously normalized host working-directory and
project-root readbacks into raw receipt fields. That was incompatible with the
security foundation's rule that exact paths remain control-plane-only: a real
host readback would either fail the receipt privacy scan or force a caller to
choose between useful evidence and safe persistence.

The normalizer now uses raw path values only in memory to verify exact equality,
then emits only `cwd_sha256`, `git_top_level_sha256`,
`project_root_sha256`, and the existing source object digests. Verification
accepts only the redacted canonical fields and checks any supplied raw value
against its digest before discarding it. The receipt therefore remains
source-bound without retaining a user path.

Static evidence after this repair: the controller and focused verifier pass
syntax checks, the updated JSON binding parses, and diff hygiene passes. The
focused functional verifier remains pending under campaign policy. This repair
does not change PF-004 or release feature admission.

proof holds.
